Claude Code הוא כלי ההנדסה היומיומי שלי בכל הפרויקטים הנוכחיים. זה גם הכלי שהמערך ציין בכנס הספקים ככלי העבודה בפיתוח המערכת.

כליאיך אני עובד איתו
Claude Codeכלי העבודה היומיומי שלי. כל Session מתחיל מקריאת כללי הפרויקט, ה-Spec וההקשר הרלוונטי. אני עובד עם Skills, Worktrees ובדיקת אדם לכל שינוי.

מודלים: Claude, OpenAI, Geminiבמוצרי Agent אני עובד מול כמה ספקי מודלים דרך שכבת Routing אחת. הבחירה במודל מתועדת ונמדדת לפי משימה, עלות ותוצאה.

מתודולוגיה במצגת טלוסאיך זה נראה אצלי
SDDה-Spec נכתב לפני קוד ונשמר ב-Repository ליד הקוד. תיקון או תוספת מתחילים בעדכון ה-Spec ולא בשינוי ישיר בקוד.
Agile/Scrumניהול Feature delivery מתוך Task Board, מחזורים קצרים, בעלים לכל משימה ופרסום רציף לאחר אישור.

SDD לפי ארבעת הקבצים

קובץמה אני עושה בפועל
SPECלכל Feature נכתב Task Spec לפני פיתוח. התבנית כוללת Background, What Changes, Out of Scope, Files Touched ו-Acceptance Criteria. במערכת Aspect קיימים 55 Task Specs ו-78 מסמכי הנחיה, תכנון ו-Feature.
PLANמפרט גדול מפורק לשלבים. לכל שלב יש Gate, ובחלק מהשערים מוגדר במפורש Human Review Required. הכלל הוא לא לדלג על שערים.
Progress and logsבתוך ה-Spec יש Checklist לביצוע, יומן הרצה, החלטות נעולות וחריגות מהאפיון. משימה מסומנת כהושלמה רק לאחר שסעיף ה-Verify עבר ותועד.
Validationסוללות בדיקה pass/fail, Replay של שיחות לקוח, תיקיית Verification עם README לכל נושא, Code Review אנושי ו-Merge ל-Master. Release הוא צעד נפרד ומאושר.

3. פרויקטים

שני הפרויקטים המרכזיים הם מערכות ב-Production, שנבנו עם Claude Code ובתהליך SDD.

פרויקט 1: פלטפורמה לבניית סוכני AI ללא קוד (פרויקט לקוח)

שדהפירוט
תיאורהפלטפורמה תוכננה ונבנתה על ידי עבור לקוח. הקניין הרוחני שייך ללקוח, ולכן התיאור כללי וניתן להרחיב עליו בכפוף לאישורו. הפלטפורמה מאפשרת לאנשים שאינם מפתחים לבנות, לבדוק ולהפעיל סוכני AI ללא קוד. הסוכנים מתכננים לפני מענה, מפעילים כללים עסקיים קבועים כשאפשר להגדיר כלל, ואינם מסתמכים על Prompt יחיד גדול.
טכנולוגיות וכליםNode.js 22, Express 5, React 19, TypeScript, PostgreSQL על Google Cloud SQL עם Drizzle ORM, Pinecone, Google Cloud Run, Cloud Scheduler, Firebase Hosting ו-SSE streaming. העבודה נעשית עם Claude Code, מסמכי Markdown ב-Repository ובדיקות Feature.
ממשקיםAnthropic, OpenAI ו-Google Gemini דרך שכבת Routing אחת. Web chat, Widget להטמעה, WhatsApp דרך Meta Cloud API ו-Twilio, ו-Knowledge Bases.
משך הקמהמוקאפ ומסמך ארכיטקטורה ראשונים ב-5.4.2026. גרסה עובדת ראשונה ב-21.5.2026, כ-7 שבועות לאחר מכן, על גבי Runtime קיים. יכולות נוספות נוספו באופן מדורג מיוני עד ספטמבר 2026.
מתודולוגיהSDD עם מסמך תכנון מפורט ומסמכי משנה. לכל Feature יש Task Spec, החלטות מתועדות, Checklist מחייב לאחר Feature וסוללות בדיקה. כל Session קורא כללי פרויקט מתוך CLAUDE.md לפני תחילת עבודה.
אתגרים ופתרונותשליטה מול Prompt גדול אחד → פירוק לשלבים מבוקרים וכללים קבועים; עוזר AI עלול לפגוע בסוכן בעת עריכה → הצעות בלבד, Validation, Change Log, אישור אדם, גרסאות ו-Revert; שינוי עלול להגיע למשתמשים בטעות → Publish נפרד; תיעוד וידע העוזר עלולים להתיישן → Checklist מחייב לאחר כל Feature.
זמן באווירב-Production מאז מאי 2026, כ-5 חודשים, ובפיתוח רציף.
מסקנות ולקחיםיש להעדיף כלל קבוע כאשר אפשר לנסח את הכלל העסקי. Spec בכל רמת פירוט מאפשר לעוזר AI לבצע שינוי נכון. שינויים נמדדים גם על שיחות אמיתיות ולא רק על תרחישים שהומצאו מראש.
חדש או שיפורדור שני של מערכת קיימת. נבנה ממשק חדש לבניית סוכנים על גבי Runtime קיים.
התפקיד שליארכיטקט ומוביל מוצר, מפתח Hands-on ומוביל צוות של שלושה (אני ושני מפתחים).

איך עבדנו עם הסוכנים בפרויקט 1

  • Claude Code מימש משימה מתוך ה-Spec על Branch ייעודי.

שדהפירוט

טכנולוגיות וכליםNode.js 22, Express 5, React 19, TypeScript 5.9, Vite, PostgreSQL על Google Cloud SQL, Pinecone, Cloud Run, Cloud Storage, Cloud Scheduler, Firebase Hosting ו-Docker. קיימים כ-124,000 שורות Server Code וכ-150,000 שורות TypeScript בצד הלקוח.
ממשקיםAnthropic, OpenAI ו-Gemini. טעינת נתונים מ-Google Drive מקובצי CSV ו-QlikView QVD, WhatsApp ו-Google Sign-In. טעינת מידע נעשית ל-Shadow Schema ולאחר בדיקה ב-Atomic Swap.

מתודולוגיהSDD עם Claude Code. לכל משימה יש Spec, Acceptance Criteria, תוכנית בשלבים עם Gates, יומן ביצוע ותיקיית Verification. העבודה מנוהלת על Branches, עם Review אנושי לפני Merge ו-Release ידני.
אתגרים ופתרונותמספרים שגויים הם הסיכון המרכזי → הקוד מבצע את החשבון והמודל מבצע שיפוט, ללא SQL חופשי ב-Dashboard; שאלות שאין עליהן נתון → Pre-check מבוסס Manifest שמסרב בתוך כ-1 ms; אי-דטרמיניזם → יצירת SQL ב-Temperature 0; עברית ו-RTL → Suites ייעודיים ותיקוני אותיות סופיות; ביצועים → Timeout של 15 שניות, Materialized Views ואופטימיזציית שאילתות; בידוד לקוחות → Schema נפרד לכל לקוח; עלות → Model registry, לוג שימוש ומגבלות הוצאה.
זמן באווירב-Production מאז פברואר 2026, כ-7.5 חודשים, ובפיתוח רציף. בשני ה-Repositories קיימים כ-1,790 Commits בכ-9 חודשים.
מסקנות ולקחיםסט של 65 תרחישים מומצאים עבר במלואו, אך Session אמיתי של 18 שאלות חשף שתי תשובות שגויות. מאז מבוצע Replay של שיחות אמיתיות. לאחר תקלה שבה דגל Deploy השמיט Secrets, כל Deploy מאמת את ה-Live Revision. כל שינוי דיוק נמדד לפני ואחרי.

התפקיד שליCTO וארכיטקט, מפתח Hands-on, מוביל צוות של שלושה (אני ושני מפתחים) ואחראי על Releases.

סה"כ

התאים הלבנים ניתנים לעריכה. השינויים נשמרים בדפדפן שלך בלבד.

  • שעות ליחידה מחושבות כמספר הימים ליחידה כפול שעות עבודה ביום, והימים נלקחו מטבלת ה־SLA במכרז.
  • ה־SLA מגדיר זמן אספקה של צוות סטנדרטי, ולכן הוא בסיס שמרני להערכת שעות.
  • הטבלה אינה כוללת Discovery למערכת קיימת (לימוד המערכת הקיימת), שלדעתי רלוונטי כי הספק הזוכה נדרש להכיר את המערכת: 7 ימים למערכת קטנה ו־13 ימים לגדולה.
  • תחזוקה שנתית מתומחרת במכרז בשיעור של 12% ולא בשעות, ולכן אינה כלולה בטבלה.
